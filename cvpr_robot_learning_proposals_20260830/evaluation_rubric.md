# Proposal 独立评审量表

版本：1.0  
生效日期：2026-08-30  
适用对象：`GEO-P1`、`GEO-P2`、`GEO-P3`、`WAM-P1`、`WAM-P2`、`WAM-P3`、`STR-P1`、`STR-P2`、`STR-P3`、`JEP-P1`、`JEP-P2`、`JEP-P3`

## 1. 评审原则

本量表评估的是一份可以被实现、被证伪、被强基线攻击的 CVPR 研究 Proposal，而不是题目是否“听起来新”。每个判断必须指向 Proposal 中的具体文本、公式、信息路径、数据协议或实验表；缺少证据时不得按最有利解释补全。

评分使用 `1.0–5.0`，以 `0.5` 为最小增量。除非本轮核查了实际修改，分数不得改变。分数不要求逐轮上涨；发现新的最近邻、信息泄漏或不可实现条件时必须下降。

### 通用分数锚点

| 分数 | 含义 |
|---|---|
| 1.0 | 核心命题错误、无定义或与已知工作实质重复；无法通过小修复挽救。 |
| 1.5 | 有研究主题但没有可执行问题；存在多个致命缺口。 |
| 2.0 | 问题可辨认，但机制、证据或实验大多是口号。 |
| 2.5 | 有局部技术内容，但关键因果链、数据或对照不成立。 |
| 3.0 | 可形成普通实验计划；仍有一个严重缺口或若干大缺口。 |
| 3.5 | 基本完整；审稿人仍可用一个强攻击面否定主要结论。 |
| 4.0 | 强且可执行；缺口为非致命、可在论文周期内补齐。 |
| 4.5 | 证据链、最近邻差异和压力测试均清晰；只能提出次要保留意见。 |
| 5.0 | 近乎提交就绪：定义、理论/机制、数据、实验和风险边界互相闭合，且已预注册关键判据。 |

## 2. 十五个必评维度

每轮每个 Proposal 必须逐项给分并附理由。不得合并维度，也不得只给总评。

### D1 问题重要性

- `1–2`：失败不影响真实控制，或只是提高常规 benchmark 数字。
- `3`：问题真实但影响范围、频率或代价没有量化。
- `4`：给出任务族、失败频率/代价和受影响现有方法；能解释为什么值得 CVPR 社区关注。
- `5`：有跨模型、跨任务的实证先验，且解决后会改变常用建模或评测方式。

### D2 失败模式清晰度

- `1–2`：把“泛化差/不稳定”当失败定义。
- `3`：有现象描述，但潜变量、观测条件和反例未隔离。
- `4`：以可观测变量、受控干预、触发条件和失败指标定义；能与相邻失败区分。
- `5`：包含最小生成过程、正/负例、混淆因素与可复用诊断 benchmark。

### D3 创新性与最近邻差异

- `1–2`：模块重命名、简单拼接，或最近邻已经覆盖核心命题。
- `3`：实现不同但科学问题/证据主张与最近邻基本相同。
- `4`：对至少三篇最强最近邻给出逐项差异：输入、监督、训练/推理图、机制、实验结论。
- `5`：差异落在新的可检验科学命题，而非组件；主动包含冲突性工作并说明什么结果会使新意失效。

### D4 机制因果闭环

- `1–2`：从模块直接跳到成功率。
- `3`：有中间指标，但不证明该指标驱动动作改进。
- `4`：`失败原因 → 机制 → 中间可观测量 → 决策变化 → 任务结果` 每一箭头都有干预或对照。
- `5`：包含因果中介、交换/删除/随机化干预及替代解释排除。

### D5 技术正确性

- `1–2`：数学、时序、控制或学习目标不自洽。
- `3`：总体可行，但符号、损失、训练稳定性或部署路径存在大空白。
- `4`：张量/时间索引、损失、优化、控制频率和复杂度一致；失败保护明确。
- `5`：关键性质有推导、边界条件或单元测试设计，并讨论退化解与优化冲突。

### D6 具身可观测性与信息泄漏

- `1–2`：推理使用未来帧、未来真值、模拟器状态、成功标签或不可部署传感器而未声明。
- `3`：声称因果但未画训练/推理可见性表；伪标签或时间窗可能泄漏。
- `4`：逐 token/模态列出 train-time 与 test-time 可见信息、时间戳和 stop-gradient；有 action-shuffle/future-mask 等泄漏负控。
- `5`：除形式审计外，还用故意泄漏阳性对照、严格因果重跑或部署日志证明无捷径。

### D7 数据可得性

- `1–2`：关键标签或传感器数据不存在且没有采集预算。
- `3`：数据源存在，但许可、规模、同步、标定、伪标签质量或划分未知。
- `4`：列出公开数据/自采数量、许可、字段、生成脚本、质量审计和 train/val/test 划分。
- `5`：关键最小实验完全可由可访问数据复现，并有标注误差与域偏差敏感性计划。

### D8 算力与工程可行性

- `1–2`：依赖未发布模型、超大规模预训练或未知硬件。
- `3`：能实现但预算、显存、训练时长、真机占用或系统延迟缺失。
- `4`：给出最小/完整两档预算、GPU/显存/时长、吞吐、缓存和失败回退；资源与实验表匹配。
- `5`：有可复用开源基线、单机 smoke test、profiling 计划和超预算降级路径。

### D9 实验可证伪性

- `1–2`：任何结果都能被解释为支持方法。
- `3`：有指标，但没有预先声明否定主张的阈值或结果模式。
- `4`：列出主假设、主要终点、统计单元、阈值、置信区间，以及明确的“失败则放弃/降级主张”。
- `5`：关键检验能区分至少两个竞争机制，并预注册多重比较、样本量或顺序检验。

### D10 基线强度

- `1–2`：只比老旧或弱基线。
- `3`：有强模型但训练数据、容量、推理预算或调参不匹配。
- `4`：包含截至 2026-08-30 的直接最近邻、强通用基线、简单控制和 oracle；数据/参数/算力匹配。
- `5`：除作者复现外还含官方 checkpoint/代码基线、等算力与等延迟 Pareto 比较。

### D11 消融充分性

- `1–2`：只有 full vs. baseline。
- `3`：拆模块但不拆监督、数据或计算量。
- `4`：对机制、监督、信息源、容量、数据量和推理计算做正交消融，并含随机/无信息对照。
- `5`：加入必要性与充分性干预、替代机制、超参敏感性和交互项分析。

### D12 OOD 与真实机器人有效性

- `1–2`：仅训练同分布仿真成功率。
- `3`：有随机化但未隔离 OOD 轴，或真机 trial 太少。
- `4`：至少覆盖两个机制相关 OOD 轴、逐轴报告、真实机器人任务与失败分类；不把背景变化当物理泛化。
- `5`：跨相机/物体/布局/动力学/embodiment 中至少三个相关轴，含 exact-reset 或配对试验和足够 trial。

### D13 复现性

- `1–2`：缺少实现和协议细节。
- `3`：列出代码框架但缺少种子、配置、数据处理或评估脚本。
- `4`：提供环境、版本、随机种子、训练/评估伪代码、checkpoint、日志字段和 artifact 清单。
- `5`：从原始数据到表格的一键路径、确定性 smoke test、失败重跑规则与成本表齐全。

### D14 CVPR 契合度

- `1–2`：主要是机器人系统集成，没有视觉学习问题或视觉证据。
- `3`：视觉只是输入；贡献更像控制或系统论文。
- `4`：视觉表征/预测/几何/时序学习是主机制，视觉 benchmark 与具身结果互相支撑。
- `5`：产生可推广到计算机视觉的新表示、评测或学习结论，同时具备强视觉分析。

### D15 风险与负结果价值

- `1–2`：不讨论风险；负结果等于“没涨点”。
- `3`：列出风险但无监测、缓解或替代产出。
- `4`：每个高风险项有早停指标、缓解方案；核心假设失败仍产出 benchmark、诊断或边界结论。
- `5`：负结果能区分理论解释并形成可发布的设计准则；安全/隐私/硬件风险有操作协议。

## 3. 硬门槛与致命缺陷

Proposal 只有同时满足下列条件才可标记 `PASS`：

1. 已完成并收到独立评审的轮次不少于 `round_10`；第 10 轮之前一律 `FAIL`。
2. 十五维每一维 `>= 4.0`。
3. 十五维算术平均 `>= 4.30`，保留两位小数。
4. `D3 创新性`、`D5 技术正确性`、`D6 可观测性/泄漏`、`D9 可证伪性` 均 `>= 4.5`。
5. 不存在下列任何 fatal flaw。

Fatal flaw 包括但不限于：

- 核心贡献被截至 2026-08-30 的最近邻完整覆盖，差异只剩工程拼接或命名。
- 推理路径依赖不可获得的未来真值、模拟器状态、人工标签或事后成功信息。
- 主要实验无法区分提出机制与额外数据、参数、教师、采样步数或控制频率。
- 不存在能否定主要假设的可执行实验。
- 数据、代码、算力或机器人平台的必要条件在项目周期内不可获得。
- 主要指标存在评估泄漏、非独立统计单元、基线预算不公平或不可修复的 protocol mismatch。

`PASS` 不表示没有风险。非致命风险必须写入最终证书，并明确为什么不会推翻主要结论。

## 4. 分轮评审深度

每轮仍需完整评分十五维；下列主题只是该轮的主要压力测试。

| 轮次 | 主要压力测试 |
|---|---|
| round_01 | 问题、失败模式、科学命题与最小反例。 |
| round_02 | 最近邻、冲突性工作、创新边界与同义重命名。 |
| round_03 | 机制因果链、训练/推理信息图、具身可观测性与泄漏。 |
| round_04 | 公式、时间索引、目标函数、优化退化解、控制与系统正确性。 |
| round_05 | 可证伪假设、主要终点、统计功效、判负阈值与竞争解释。 |
| round_06 | 强基线、等预算比较、oracle、正负控、必要/充分消融。 |
| round_07 | 数据字段/许可/划分、算力、工程路径、复现 artifact。 |
| round_08 | OOD 轴、真机协议、风险、安全性与负结果价值。 |
| round_09 | CVPR 叙事、视觉贡献、审稿人攻击面与 claim 收缩。 |
| round_10 | 全量压力测试：独立复算、最近邻刷新、信息泄漏审计、资源核对和最终判定。 |
| round_11+ | 仅针对未过门槛项继续；不得用文字润色替代结构性修复。 |

## 5. 每个独立评审文件的强制结构

路径：`reviews/round_XX/<proposal-id>.md`

每份必须包含：

1. `Proposal-ID`、被审 Revision、文件路径、核查时间、本轮结论。
2. 文件变更核验：与上一轮相比实际新增/删除/修改了什么。
3. 十五维评分表：分数、文件内证据、评审理由。
4. 平均分和四个关键维度门槛检查。
5. Top 问题，按 `fatal / major / minor` 分级。
6. 最近邻冲突与证据缺口，含版本和链接。
7. 可执行修改动作：应落到公式、表格、实验、数据或措辞。
8. 下一轮验收条件：可二元核对，禁止写“进一步完善”。

每轮 `summary.md` 必须列出 12 个 ID、Revision、平均分、最低维、fatal flaw、轮次结论和下一轮优先级。

## 6. 版本与交接约定

- Proposal ID 永不改名；标题可以改，ID 不可改。
- 建议 Revision 使用 `r00`、`r01`……；Proposal 顶部记录 `Responds-To-Review`。
- 主笔每轮交接必须给出 12 个完整路径、Revision、实际修改摘要和 `refinement_log` 条目。
- Reviewer 必须先读实际文件并核对变化，才可创建下一轮评审。
- 文献边界在 `round_02` 与 `round_10` 至少各刷新一次；新论文可能触发降分或重新开轮。
