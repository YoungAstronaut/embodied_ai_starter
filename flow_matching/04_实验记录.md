# 04 实验记录：`code/fm_lab.py` 的结果与解读

> 跑的环境：MacBook Pro M5 Pro，CPU，PyTorch 2.14。`python fm_lab.py all` 全部跑完约 **10.5 分钟**。
> 每个模型都是 4 层、宽 256 的 MLP，训练 6000 步，batch 512，AdamW 1e-3 加 cosine 衰减。
> 图都在 `code/results/<实验名>/` 下面。fewstep 和 action 跑了 3 个种子，表里写成 均值±标准差；basics 和 coupling 只跑了 1 个种子。

---

## 0. 先说指标：SW2 在这个玩具上不可靠

我把两份**同分布**的真数据（各 4000 点）拿来算 SW2，结果在 **0.09–0.21** 之间波动（几次运行各不相同）。所以 SW2 差异小于约 0.1 的时候，都只是采样噪声。

下文主要用两个更能区分方法的指标：

- **`off_manifold`**：样本离最近模式中心超过 3σ 的比例，0 最好。它直接度量「掉在模式之间」的样本有多少，正好对应均值坍缩。
- **`mode_tv`**：各模式占比与均匀分布的 TV 距离，0 最好。度量模式比例有没有失衡。

这本身就是一条经验：**少步质量要用「落在哪里」类的指标来看**。全局分布距离被采样噪声淹没，看不出区别。

## 1. basics：vanilla FM 的步数退化

| NFE | Euler off_manifold | Heun off_manifold | 备注 |
|---:|---:|---:|---|
| 1 | **1.000** | — | 所有样本挤在原点 |
| 2 | 0.757 | 0.968 | Heun 2 次调用 = 1 步 |
| 4 | 0.202 | 0.152 | |
| 8 | 0.079 | 0.055 | |
| 16 | 0.042 | 0.031 | |
| 64 | 0.027 | 0.022 | |

直线度 $S=2.57$（0 表示完全直）。

**解读**：

1. **NFE=1 时 100% 落在模式之外，全部挤在原点。** 原点就是数据均值，因为 8 个模式对称分布。这验证了 `01` 第 4.2 节的命题：独立 coupling 下 1 步 Euler 落在 $\mathbb E[x_1]$。
2. **同样 2 次调用，Euler 2 步（0.76）好于 Heun 1 步（0.97）。** Heun 的校正只能修截断误差，修不了「第一步就走向均值」这个问题。只有在 NFE≥4、问题从均值坍缩变成曲率之后，高阶 solver 才开始占优。
   - **经验：预算很紧时，宁可多走几步 Euler，也不要用高阶 solver。**

## 2. coupling：把轨迹拉直

| | 直线度 S | 1 步 off | 2 步 off | 16 步 off | 训练时间 |
|---|---:|---:|---:|---:|---:|
| I-CFM（独立配对） | 2.586 | 1.000 | 0.758 | **0.047** | 10s |
| OT-CFM（minibatch OT，batch 512） | 0.0069 | 0.194 | 0.143 | 0.055 | 160s |
| 2-Reflow（用 I-CFM 生成配对再训练） | **0.0006** | **0.112** | 0.105 | 0.064 | 10s + 生成配对 |

**解读**：

1. 直线度下降了 3–4 个数量级，1 步质量从完全失败变成基本可用。**coupling 是少步问题的根源之一**，这一点在 toy 上被干净地证实了。
2. **代价是多步时反而略差**：16 步的 off_manifold 从 0.047 升到 0.055 / 0.064。看 `results/coupling/samples.png`，OT 和 Reflow 的样本在相邻模式之间留下了一条细细的「桥」。
   - Reflow 的配对是上一代模型生成的，**上一代的误差被固化进了配对里**；
   - minibatch OT 只是全局 OT 的近似，batch 内配对会把相邻模式的样本连起来。
3. OT 的成本：CPU 上匈牙利算法让训练慢了 16 倍。

## 3. fewstep：不拉直，直接学跳步（3 个种子）

| off_manifold | NFE=1 | 2 | 4 | 8 | 64 |
|---|---:|---:|---:|---:|---:|
| FM | 1.000±0.000 | 0.752±0.010 | 0.192±0.005 | 0.074±0.004 | 0.028±0.002 |
| Shortcut | 0.223±0.008 | 0.110±0.004 | 0.053±0.003 | 0.034±0.001 | 0.019±0.001 |
| MeanFlow | **0.171±0.004** | 0.110±0.003 | 0.054±0.002 | 0.039±0.003 | 0.026±0.001 |

训练时间：FM 10s，Shortcut 15s（×1.5），MeanFlow 22s（×2.2，因为多一次 JVP）。

**解读**：

1. 两种跳步方法在 1 步时都比 FM 好得多。在 1 步上 MeanFlow 略好，2 步以后两者基本持平。
2. **多步时两者都不比 FM 差**，Shortcut 在 64 步时甚至更好（0.019 对 0.028）。也就是说，在这个 toy 上「支持少步」没有牺牲多步质量。
3. Shortcut 的 `mode_tv` 稍高（0.033–0.040，FM 是 0.025），模式比例轻微失衡，原因我没查。
4. **不能据此给 Shortcut 和 MeanFlow 排序**：只有一种网络、一个数据集，而且两边都没调超参。

### 3.1 一个复现陷阱：MeanFlow 的自适应权重

原文用 $w=1/(\|\Delta\|^2+c)^p$，取 $p=1$。我第一版照抄，结果在 8-Gaussian 上**模式比例明显失衡**。下表是单种子诊断，三个数分别对应 NFE=1 / 2 / 64：

| 设置 | mode_tv |
|---|---|
| $p=1$，25% 样本 $s\neq t$（原文设置） | 0.209 / 0.097 / 0.069 |
| $p=0$，25% | 0.041 / 0.033 / 0.025 |
| $p=1$，50% | 0.152 / 0.128 / 0.140 |
| $p=0$，50%（**现在的默认**） | 0.031 / 0.031 / 0.029 |

**我的解释**：$p=1$ 时每个样本对损失的贡献约为 $\|\Delta\|^2/(\|\Delta\|^2+c)$，接近常数，相当于一个鲁棒损失。鲁棒损失的最优解**不是条件均值**（更接近中位数或众数）。而 CFM 整套理论都依赖「平方损失学到条件均值」这个前提。在 $t$ 很小、标签方差很大的区域，均值和中位数差得最远，于是模式比例被带偏。

**边界**：这只是 toy 上的观察。原文在 ImageNet 上 $p=1$ 最好，可能是因为高维、单模式占优等原因。**不要把它推广成「原文设置有错」**。它提醒的是：**改损失权重，就是在改回归目标的最优解。**

## 4. action：双模态绕障 action chunk（这个实验最重要，3 个种子）

任务：从 (0,0) 到 (1, goal_y)，中间 (0.5, 0) 有一个半径 0.15 的圆形障碍。示范一半从上方绕、一半从下方绕，碰撞率为 0。action chunk 是 16 个 2D 路点，共 32 维；条件是 goal_y。动作做了 z-score 归一化。

| 碰撞率 | NFE=1 | 2 | 4 | 16 |
|---|---:|---:|---:|---:|
| FM | **0.957±0.005** | 0.219±0.011 | 0.035±0.008 | 0.006±0.002 |
| Shortcut | 0.088±0.002 | 0.012±0.002 | 0.003±0.001 | 0.000±0.000 |
| MeanFlow | **0.068±0.007** | **0.004±0.004** | 0.000±0.000 | 0.000±0.000 |

各方法上绕的比例都保持在 0.47–0.56，没有出现「只学会一边」的模式丢失。

**解读**：

1. **1 步 FM 的碰撞率是 95.7%。** 它生成的轨迹和解析条件均值 $\mathbb E[A\mid c]$（左右两条绕行路线的平均，也就是一条直线）之间的平均距离只有 **0.019**，而绕行幅度是 0.3–0.4。也就是说，它**几乎精确地落在了理论预言的那条穿墙直线上**。看 `results/action/trajectories.png` 第一格就一目了然。
2. 要做到同样的安全性，FM 需要 16 步才降到 0.6%，跳步方法 2 步就能到 ~1%。**在机器人里少步的意义不是「快一点」，而是「同样延迟下不撞墙」。**
3. 这就是 `../01_研究方向梳理.md` §3.C 的现象来源：在 2D 散点图里，均值坍缩只是「糊」；到了动作空间里，它就是「撞」。

## 5. 踩到的三个实现陷阱（比结果本身更有用）

### 5.1 不做动作归一化：少步方法直接失效

把动作保持原始尺度（幅度约 0.3，噪声 std=1），其他不变：

| 碰撞率 | NFE=1 | 2 | 4 | 16 |
|---|---:|---:|---:|---:|
| FM | 0.943 | 0.399 | 0.140 | 0.036 |
| Shortcut | 0.716±0.085 | 0.189 | 0.075 | 0.023 |
| MeanFlow | 0.418±0.044 | 0.129 | 0.055 | 0.021 |

归一化以后，Shortcut 的 1 步碰撞率从 72% 降到 9%，MeanFlow 从 42% 降到 7%。

原因是：噪声尺度远大于信号时，网络要在 $v=\hat x_1-x_0$ 里精确抵消一个大的 $-x_0$，残差相对于动作幅度太大。**这是我第一次跑 action 实验时就踩到的坑**（当时以为是方法本身不行）。

### 5.2 高频时间嵌入会让 MeanFlow 训崩

`Net` 一开始用了 Fourier 时间特征（频率 $2\pi k,\ k=1..4$）。在 32 维动作上的单种子结果：

| 碰撞率（NFE=1 / 2 / 16） | n_freq=4 | n_freq=0（直接输入标量） |
|---|---|---|
| FM | 0.98 / 0.23 / 0.009 | 0.96 / 0.22 / 0.004 |
| Shortcut | 0.13 / 0.028 / 0.001 | 0.088 / 0.013 / 0.000 |
| MeanFlow | **0.63 / 0.60 / 0.61** | **0.068 / 0.009 / 0.000** |

FM 基本不受影响，MeanFlow 却完全失败，**连 16 步都不行**。

我的解释：MeanFlow 的目标里有 $\partial u/\partial s$。正弦嵌入 $\sin(2\pi k s)$ 对 $s$ 求导会放大约 $2\pi k$ 倍，自举目标的噪声随之爆炸。（训练 loss 一直在 100 以上，并且随训练**上升**。）

**经验：凡是目标里含有网络对时间求导的方法（MeanFlow、连续时间 consistency 等），时间嵌入的频率要格外小心。**

### 5.3 先用解析解验证恒等式

`code/check_meanflow_identity.py` 用高斯数据的闭式 flow map 检验 MeanFlow 恒等式：

- 正向约定下残差为 **3e-14**；
- 把符号写反后残差为 6.0。

上面 5.2 里 MeanFlow 失败时，我先跑了这个测试，排除了「符号写错」的可能，才去查优化方面的问题。**换时间约定的时候一定要先做这一步。**

## 6. 局限（别把这些结论用过头）

- 只用了 MLP 和两个 toy 数据集。没有 EMA，没有 CFG，没有超参搜索。
- action 任务是开环生成的（没有环境交互），碰撞是几何判定，不是物理仿真。
- 3 个种子只能说明方差小，不能说明结论具有泛化性。
- Shortcut 和 MeanFlow 谁更好，**在这里没有结论**。

## 7. 下一步练习（按难度排列，前两个直接通向研究方向 A）

2. **实现训练期前缀条件**（每个 token 有自己的 flow 时间，前缀取 τ=1 并且不算 loss），和 1 做对比。再把 Shortcut / MeanFlow 换进来。
3. **条件 OT coupling**：action 任务带有条件，OT 只能在同条件（或条件相近）的样本之间配对。想清楚为什么不能跨条件配对。
4. **固定 NFE 预算下的 solver 选择**：在 action toy 上比较 Euler、Heun、midpoint 在 NFE=2/4/8 时的表现。
5. **SFP 交叉轨迹反例**：构造两条相交的示范，看 SFP 怎么把它们拼接起来。
