# 03 机器人中的 FM：从 action chunk 到实时执行和 RL 微调

> 旧包的 `04_robotics_vla_application.md` 已经把 action-chunk CFM、π0、SFP 讲得很清楚，这里只做骨架复习。
> 这一份的重点是旧包没有覆盖的三块：**少步策略**、**执行层（RTC 两代）**、**RL 微调**。
> 符号：flow 时间用 $\tau$（0 = 噪声，1 = 干净动作），机器人物理时间用 $t$。**两者绝对不能混**。

---

## 1. 骨架复习：action-chunk CFM

- **生成对象**：$A=[a_t,\dots,a_{t+H-1}]\in\mathbb R^{H\times d_a}$。
- **条件**：$o$，包括图像、语言、本体状态。
- **训练**：$\|v_\theta(A^\tau,\tau,o)-(A-\epsilon)\|^2$，其中 $A^\tau=\tau A+(1-\tau)\epsilon$。
- **推理**：从 $\epsilon$ 出发积分到 $\tau=1$，执行前 $s\le H$ 步，然后重新规划。
- **π0【已核实】**：$H=50$，10 步 Euler；用 beta 分布做 time sampling，偏向噪声大的一端；VLM 前缀做一次 KV cache，只迭代动作后缀。

### 1.1 三个工程细节，决定成败

1. **动作归一化。** 我在 toy 上实测过：动作幅度约 0.3、噪声 std=1 时不做归一化，1 步和 2 步的结果几乎全是噪声。原因是网络要在 $v$ 里精确抵消一个 std=1 的 $-x_0$，残差相对动作信号太大（`04_实验记录.md` §5）。Diffusion Policy / openpi 都会先把动作归一化。
2. **NFE ≠ 步数。** Heun 一步要调用两次网络。
3. **延迟的组成。** $T\approx T_{\rm prefix}+{\rm NFE}\cdot T_{\rm expert}+T_{\rm overhead}$。RTC 论文给过一个数【已核实】：RTX 4090 上 3B 参数的 π0 光是 KV prefill 就要 46ms，而控制目标是 50Hz（每步 20ms）。所以**推理一定跨越多个控制周期**，「执行层」问题躲不掉。

## 2. 少步策略：三条路线都已经有机器人版本

| 路线 | 机器人版本 | 机制要点（详见 `02_设计空间.md`） |
|---|---|---|
| 蒸馏 | Consistency Policy（2405.07503，RSS'24） | 从 EDM 版 Diffusion Policy 出发，用 CTM 目标蒸馏到 1 步；能在笔记本 GPU 上推理 |
| 自洽 | Shortcut policy（Shortcut 论文 2410.12557 自带的机器人实验） | 以步长 $d$ 为条件，一个模型支持任意步数 |
| 平均速度 | DMPO（2601.20701） | MeanFlow + dispersive 正则 + RL 微调；RoboMimic / Gym；>120Hz |
| 拉直 | （OT coupling 用于策略的工作检索结果里有，比如 2505.01179，**没读**） | — |

**为什么少步对机器人比对图像更危险**：`01` 第 4.2 节的命题说，1 步 FM 会落到条件均值 $\mathbb E[A\mid o]$。

- 图像的均值是「糊」，看起来差，但不致命；
- 双模态动作的均值是**两条合法路径的中间**，在绕障任务里就是撞墙。

toy 实测：1 步 FM 的碰撞率约 96%（3 个种子 95.7±0.5%，见 `04` §4）。

## 3. 执行层：RTC 两代

### 3.1 问题

推理需要 $d$ 个控制周期（推理延迟）。在新的 chunk 出来之前，机器人只能继续执行旧 chunk 的动作。

- 如果新 chunk 和旧 chunk 的前 $d$ 步对不上，就会出现**跳变**；
- 在双模态的情况下，前后两个 chunk 可能选了不同的模式，表现为左右摇摆（mode jumping）。

### 3.2 推理期 RTC（2506.07339）【已核实，读了本地 PDF】

把问题看成 **inpainting**：前 $d$ 步「冻结」（必然会执行），中间一段用指数衰减的权重软约束，最后 $s$ 步重新生成。实现是在**每个去噪步**往速度场上加 ΠGDM 引导：

$$
v_{\Pi\rm GDM}=v+\min\!\Big(\beta,\ \tfrac{1-\tau}{\tau\, r_\tau^2}\Big)\,(Y-\hat A^1)^\top{\rm diag}(W)\,\frac{\partial \hat A^1}{\partial A^\tau},
\quad \hat A^1=A^\tau+(1-\tau)\,v
$$

其中 $r_\tau^2=\frac{(1-\tau)^2}{\tau^2+(1-\tau)^2}$。

- $\hat A^1$ 就是 `01` 第 4.1 节的「预测数据」那一行。
- 引导项是一个 vector-Jacobian product，要反传一次。
- **论文原话的意思是：步数少时这个算法会不稳定，所以加了裁剪系数 $\beta$。**
- benchmark：Kinetix 12 个动态任务（有官方代码仓库 `real-time-chunking-kinetix`），另有 6 个真机双臂任务。

### 3.3 训练期 RTC（2512.05964）【已核实】

- 训练时随机采样一个延迟 $d$，把前 $d$ 个动作 token 设成「干净」（每个 token 有自己的 flow 时间，前缀 token 取 $\tau=1$），并且**不对前缀算 loss**。
- 推理时直接把已提交的前缀作为条件输入，**不需要引导、没有额外开销**。
- 结论：在仿真里高延迟时优于推理期 RTC；在 π0.6 上的真机任务（搭箱子、做咖啡）表现持平，计算更省。

### 3.4 这和少步方法的交点（→ 研究方向 A）

推理期引导要靠「多个去噪步」才有地方插手。少步模型把这个空间压缩掉了，训练期条件化则绕开了它。**哪些推理期才知道的约束没法搬到训练期**（比如运行时才出现的障碍、临时的安全区域）？这就是 `../01_研究方向梳理.md` §3.A 的问题。

## 4. Streaming Flow Policy：换掉生成变量

SFP 的做法是让 flow 时间等于物理时间：从上一个动作附近的窄高斯出发，条件速度是 $v_\xi(a,t)=\dot\xi(t)-k(a-\xi(t))$，边积分边执行。

- 优点：首个动作的延迟很低；稳定项 $k$ 能起到反馈作用。
- 代价：只保证每一时刻的**边际**分布，不保证整条轨迹的**联合**分布。示范轨迹相交时，生成的轨迹可能把两段示范拼在一起。

旧包 `04` 第 6 节讲得很好，这里不重复。

## 5. RL 微调生成式策略

**核心难点**：PPO 这类算法需要 $\log\pi(a\mid o)$，而 ODE flow 的似然要对散度做积分，又贵又不稳定。

| 方法 | 怎么拿到似然 | 状态 |
|---|---|---|
| DPPO（2409.00588，ICLR'25）【已核实】 | 把去噪链看成**内层 MDP**，每个去噪步是高斯转移，于是有逐步似然，外层环境 MDP 照常做 PPO | 有开源代码；robomimic、Furniture-Bench；有 sim-to-real |
| ReinFlow（2505.22094，NeurIPS'25）【已核实】 | 往 flow 的确定性路径里**注入可学的噪声**，把它变成离散时间马尔可夫过程，似然精确可算 | 能微调 RF 和 Shortcut 策略，1–4 步都可以；有开源代码 |
| DMPO（2601.20701）【已核实，读了摘要】 | MeanFlow 1 步 + RL | 只读了摘要 |
| 噪声空间 RL（2506.15799，**只看到标题**） | 不改动策略本身，在初始噪声 $\epsilon$ 上学一个策略 | **待读** |

**和 Agentic RL 的对应关系【判断】**：

| Agentic RL（LLM） | 生成式机器人策略 |
|---|---|
| rollout logprob 是行为策略的近似（Missing Old Logits） | 去噪链似然 / 注入噪声后的似然也是近似 |
| token / turn / trajectory，用哪个做优化单位 | 去噪步 / 动作 / chunk，用哪个做优化单位 |
| 异步 rollout 与 staleness | 异步执行（RTC），推理延迟 |
| OPD 合并能力 | Consistency 蒸馏、少步化 |
